# [ARO-007] Keep what the operator creates in `conf/` writable across container restarts

**Status**: In Progress
**Priority**: Medium
**Component**: `tasks/main.yml`
**Related**: [ARO-006](aro-006.md) — reshapes the same permission tasks;
OHC-002 in the consuming project, where this showed.

**Summary**:
As the operator, I want every file and folder I create in the two trees — by a
git checkout in particular — to stay writable for me after openHAB restarts, so
that switching branches and committing on the host keep working between two
role runs.

**Description**:
The openHAB image's entrypoint runs `chown -R openhab:openhab "${OPENHAB_HOME}"`
on every container start. It hands everything under the mounted `conf/`,
`userdata/` and `addons/` to the service account and leaves each mode as it
is. The operator's access rests on the group bits, which the role sets to
`u=rwX,g=rwX,o=` recursively — but only when it runs.

Anything created between two runs gets its creator's umask: `755` and `644`
from a git checkout. While the operator owns it, that does not matter. After
the next container start the service account owns it, the group bits give the
operator read access only, and git fails. Found 2026-10-20 on a real host: a
checkout of a conf-repo branch added `automation/js/`, openHAB restarted, and
`git reset --hard` failed with `Permission denied` on a file in it. A role run
repairs it until the next new folder. The same holds for the folders git
creates inside `.git`, such as `objects/xx/`.

A default ACL survives the entrypoint's `chown` and overrides the creator's
umask: with `default:group:<service account>:rwX` on a tree, anything created
inside it is group-writable from the start. `ansible.posix.acl` sets it and
needs the `acl` package on the host.

This interacts with ARO-006, which narrows the recursive `mode` to the places
the operator works. Both reshape the same tasks and should be designed
together.

**Scope Decisions** (2026-10-31):
- **ARO-007 first, ARO-006 after.** This item places the default ACL where
  ARO-006 will narrow the recursive `mode` to; ARO-006 then only narrows the
  `mode` and drops the second ownership walk.
- **The default ACL goes on `conf/` as a whole and on `userdata/.git`**, not on
  all of `userdata/`: openHAB writes there, the operator only runs git.
- **It grants the service account's group**, `default:group:<service
  account>:rwX` — the operator reaches the trees as a member of that group,
  as with the modes.
- **The role installs the `acl` package** — the supported platforms are Debian
  only, and a prerequisite left to the README is one a fresh host misses.
- **The permission tasks move to `tasks/permissions.yml`**, so a focused
  Molecule scenario can converge them alone, as `git-seeding` does `git.yml`.
- **Released as `v1.0.1-rc1`** — a fix on top of `v1.0.0`. The real-host check
  runs the operator's way: bump the consumer's pin, run the role, check out a
  conf-repo branch that adds a folder, restart the container, `git reset --hard`.

**Acceptance Criteria**:
- [ ] A folder and a file the operator creates under `conf/`, after a role run
      and with umask `022`, are still writable for the operator after the
      container restarts — checked on a real host, the way this was found.
- [ ] The same holds inside each tree's `.git`, so checkout, commit and reset
      keep working in both trees.
- [ ] A Molecule scenario simulates the entrypoint's `chown -R` and fails when
      the operator loses write access to something it created.
- [ ] Released RC-first, like ARO-002.

**Out of scope**:
- The modes of what openHAB itself writes — ARO-006.
